# Second Independent Validation Package

This folder contains everything you need to perform an **independent spot‑check** of the final JSON data (`proposals_75_HCoder2_final.json`). The purpose is to provide a lightweight, reproducible second validation that can be documented in a Q1 journal manuscript.

## Contents

| File | Description |
|------|-------------|
| `sample_script.py` | Python script that randomly selects a configurable percentage of passages from the final JSON and writes a `validation_sample.json` file. |
| `SECONDARY_VALIDATION_TEMPLATE.md` | Markdown template for the validation log that the secondary author (Coder 2) will fill out after the spot‑check. |
| `validation_instructions.md` | Detailed, step‑by‑step instructions on how to run the script, open the PDFs, verify the visual flags, and complete the log. |
| `validation_checklist.xlsx` | Optional Excel checklist (generated by the script) that lists case‑ID, passage path, page/line numbers, and a column for the reviewer’s “OK/FAIL” mark. |

## How to Run the Spot‑Check

1. **Open a terminal** in the root of the project (e.g., PowerShell in `C:\Users\biran\Desktop\University Coding`).
2. **Activate the existing virtual environment** (if not already active):
   ```powershell
   .\.venv\Scripts\Activate.ps1
   ```
3. **Install any missing packages** (the script only uses the standard library, so this step is usually unnecessary):
   ```powershell
   pip install -r requirements.txt   # optional, for other project deps
   ```
4. **Run the sampling script**. By default it selects **5 %** of passages (≈ 150 rows). You can adjust the `SAMPLE_FRACTION` variable inside the script.
   ```powershell
   python Second\ Indep\ Check\ 22\sample_script.py
   ```
   This will produce two files in the same folder:
   * `validation_sample.json` – the raw JSON objects for the sampled passages.
   * `validation_checklist.xlsx` – a nicely formatted Excel sheet you can open in Excel or LibreOffice.
5. **Open the resulting `validation_checklist.xlsx`**. For each row:
   * Locate the PDF page/line referenced (the script copies the `page` and `line_start` fields from the JSON).
   * Visually confirm that the `visual_reading_order_checked` flag is indeed `true` and that the `visual_review_note` accurately reflects the PDF layout.
   * Mark the **Result** column as `OK` if everything matches, or `FAIL` with a short comment if not.
6. **Fill out the validation log** using the provided template:
   ```powershell
   notepad SECONDARY_VALIDATION_TEMPLATE.md
   ```
   Replace the placeholder text with the actual numbers (e.g., total sampled, number of OK/FAIL, date, and signature).
7. **Commit the evidence** to the repository (optional, but recommended for full transparency):
   ```powershell
   git add "Second Indep Check 22/validation_sample.json" "Second Indep Check 22/validation_checklist.xlsx" "Second Indep Check 22/SECONDARY_VALIDATION_TEMPLATE.md"
   git commit -m "Add second independent validation log and data"
   git push
   ```
